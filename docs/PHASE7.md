# Phase 7 — technical SEO and performance

Historical report: later phases and the UI redesign are now covered in [COMPLETION.md](COMPLETION.md).

Verified on 2026-10-18 (Asia/Tehran). Scope: phase 7 implementation and verification
of the existing phase 1–6 code. No phase 8–12 implementation or deployment.

## Initial state and plan

The workspace contained modular accounts, catalog, orders, payments, core and
storefront apps, five project migrations, templates and tests. There was no Git
repository, README, `.env`, virtual environment or active Docker engine. Files
named `cp` and `str` were empty and were preserved. No `AGENTS.md` applied.

Read settings, dependency declarations, models, migrations, URL configurations,
domain services, templates, scripts and existing tests before editing. Preserve
database schemas and public routes, add SEO over actual catalog data, bound
catalog rendering, precompute responsive images, replace browser-time Tailwind
with compiled CSS, then test with isolated services and browsers.

Baseline: 84 tests passed with Django 5.1.6, SQLite and LocMemCache. Four existing
catalog UI tests lived under `templates/storefront/tests/` and were not discovered
by `test apps`; they were moved unchanged into `apps/storefront/tests/`.

## Delivered behavior

- Dynamic titles and descriptions, including category and paginated titles.
- Canonical URLs built from a configured `SITE_URL`, independent of request Host.
- Crawlable `/shop/category/<grade>/` routes; existing query-based filters remain
  usable. Internal category links now use those routes. Unknown grades return 404.
- Explicit index allowlist: home, plain catalog, plain categories and product
  pages. Search, filters, sorting, tracking queries, variant queries, private
  pages, JSON APIs, redirects and errors receive `X-Robots-Tag: noindex, follow`.
  HTML templates also contain matching robots metadata. Sensitive pages omit
  canonical URLs; their access control remains the existing authentication code.
- Pagination is 24 products per page, performed in SQL before prefetching/rendering.
  Sorting uses authoritative variant prices; inactive packaging/batches are
  excluded. Invalid pages return 404. Page 2 has its own canonical URL.
- `robots.txt` advertises a sitemap index. Sitemaps contain home, catalog,
  categories and active products only, with 1,000-product sections. The index
  links every section page and uses the canonical origin. Private paths remain
  crawlable so crawlers can see their noindex response; robots.txt is not access
  control.
- Visible breadcrumbs and BreadcrumbList use the same data. Product/Offer
  schema uses the selected active variant's SKU, effective price and stock.
  Prices use IRR; the UI continues to show tomans. Client variant changes update
  schema too. Missing offers, ratings, reviews and laboratory claims are never
  manufactured for schema. JSON-LD escapes HTML-significant characters.
- Versioned 400/800/1200px WebP derivatives are generated by
  `optimize_catalog_images`, preserving original files. Cards use responsive
  lazy images; the hero image has explicit dimensions and high fetch priority.
  Missing derivatives fall back to originals; no image decoding occurs during
  web requests. Re-run the command after changing images. Gallery switching
  removes old picture sources so the chosen original actually appears.
- Tailwind CSS is compiled and minified locally. Font/CDN requests and the
  runtime Tailwind compiler were removed; Persian uses the system font fallback.
  Reduced-motion preferences are respected. No shared page caching was added
  because public pages contain personalized cart/session navigation.

## Architectural decisions and tradeoffs

| Decision | Problem and reason | Limitation / future dependency |
| --- | --- | --- |
| Shared indexing policy | Prevent disagreement between HTML and API/error headers | New public phase-8 content must be explicitly added |
| Configured origin | Avoid Host-header canonical/sitemap poisoning | Production requires explicit HTTPS `SITE_URL`; configure the real domain |
| Canonical + noindex facets | Preserve filtering without indexing duplicate result permutations | Filtered/variant query URLs are intentionally excluded from search |
| SQL pagination and prefetch | Bound page size and prevent per-product database queries | Counts and aggregate sorting still need profiling on large datasets |
| Precomputed versioned WebP | Avoid expensive image conversion in request handlers | Run after uploads; old derivative cleanup is an operational follow-up; square crops may need art direction |
| Compiled CSS, local system font | Remove external render-blocking dependencies | Rebuild CSS after template/JS class changes; font appearance varies by OS |
| Django 5.2 LTS, patched Pillow | Existing Django 5.1 series was unsupported; image audit found vulnerable Pillow | Dependency audit is time-specific, not proof of absence of all defects |
| Isolated verification Compose | Real PostgreSQL locks and Redis without touching other project services | Ephemeral demo database; not production infrastructure |

Dependency pins now include Django 5.2.18, Pillow 12.3.0 and their installed
shared Python dependencies. Existing psycopg/Redis/coverage/Gunicorn direct pins
remain. Tailwind/CLI 4.3.0 and Playwright 1.64.1 are exact development pins with
`package-lock.json`. `npm audit fix` updated compatible watcher dependencies;
the final lock has zero reported advisories. The compiled CSS is included, so
Python runtime/Docker do not require Node to serve it. After changing classes,
rebuild it before packaging. No migration or existing data transformation.

## Verification of previous phases — remaining findings

Passing tests do **not** establish production readiness of all previous phases:

1. **Phase 2, high priority:** OTP dispatch checks cooldown/hourly limits before
   sending SMS and persists state afterwards. Verification reads and writes
   challenge attempts non-atomically. Parallel requests can bypass limits or
   race consumption. The tested Redis sequential cases pass; a Redis Lua/atomic
   design and concurrent authentication tests remain required. The only SMS
   provider supplied is a sandbox.
2. **Phase 5, high priority:** `ZarinpalV4Gateway.refund_payment` returns success
   and a generated reference without contacting a refund API. This is a local
   ledger entry, not evidence of a bank refund. Must be corrected before live
   refunds. Gateway tests use mocks/sandbox; no live merchant transaction or
   external refund was attempted.
3. **Phase 6, content:** demo seeding creates synthetic images, certificates,
   laboratory values and prices. These are stored in the isolated demo database
   only; they must not be presented as actual inventory/quality evidence in a
   live store. Existing home/marketing copy also needs review against real
   certificates before launch. Schema does not assert those laboratory claims.
4. **Phase 12 dependency:** a passing production settings check used a sample
   domain. Real HTTPS, Nginx/media rules, durable Redis sessions, backups,
   deployment and live-provider credentials were not configured or tested.

These are documented findings, not changes to the business logic of earlier
phases. Database schemas and payment/auth flows were preserved.
